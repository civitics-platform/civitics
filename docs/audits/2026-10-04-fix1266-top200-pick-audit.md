## 1. Method — the queries, verbatim

The population (read 3's base query, run as a CTE inside each query below):

```sql
WITH top AS (
  SELECT donor_id, max(donor_name) AS donor_name, max(entity_type) AS entity_type,
         sum(total_cents) AS cents, count(DISTINCT official_id) AS officials
  FROM official_donor_rollup_mv
  WHERE donor_id IS NOT NULL AND relationship_type = 'donation'
  GROUP BY donor_id ORDER BY cents DESC LIMIT 200
)
```

The IE population is the same with `relationship_type IN ('ie_support','ie_oppose')`
and `LIMIT 50`. Then, for those ids, one query each:

```sql
-- q1  the population, ranked
SELECT jsonb_agg(to_jsonb(t) ORDER BY t.cents DESC) FROM (
  SELECT row_number() OVER (ORDER BY cents DESC) AS rk, * FROM top) t;

-- q2  the entity
SELECT jsonb_agg(jsonb_build_object('id', fe.id, 'name', fe.display_name, 'canonical_name', fe.canonical_name, 'primary_source', fe.primary_source, 'entity_type', fe.entity_type,
  'fec_committee_id', fe.fec_committee_id, 'is_synthetic', fe.is_synthetic,
  'cmte_type_raw', fe.metadata->>'fec_cmte_type_raw', 'connected_org', fe.metadata->>'fec_connected_org_nm'))
FROM public.financial_entities fe WHERE fe.id IN (SELECT donor_id FROM top);

-- q3  every industry row
SELECT jsonb_agg(jsonb_build_object('entity_id', et.entity_id, 'tag', et.tag, 'generated_by', et.generated_by,
  'confidence', et.confidence, 'metadata', et.metadata,
  'created_at', et.created_at))
FROM public.entity_tags et
WHERE et.entity_type = 'financial_entity' AND et.tag_category = 'industry'
  AND et.entity_id IN (SELECT donor_id FROM top);

-- q4  the pick
SELECT jsonb_agg(to_jsonb(p)) FROM public.primary_industry_tag((SELECT array_agg(donor_id) FROM top)) p;

-- q5  any override, both arms
SELECT jsonb_agg(to_jsonb(o)) FROM public.financial_entity_industry_overrides o
WHERE o.financial_entity_id IN (SELECT donor_id FROM top)
   OR o.fec_committee_id IN (SELECT fe.fec_committee_id FROM public.financial_entities fe
                             WHERE fe.id IN (SELECT donor_id FROM top) AND fe.fec_committee_id IS NOT NULL);
```

Each ran in ≤ 2 s. The donation base aggregates 644,964 of the table's 658,492
rows (402,949 distinct donors). The rule keyword shown beside each rule pick is
recomputed from `INDUSTRY_KEYWORDS` (`packages/data/src/pipelines/tags/rules.ts`)
with the tagger's own matcher (substring; keywords of ≤ 4 characters
word-bounded) against the entity's current `display_name`.

## 3. Verdict rules — stated first, applied mechanically

A verdict judges the pick a reader sees today. The vocabulary:

- **right** — the pick is correct, or there is no pick and *no industry* is
  correct.
- **wrong → key** — the pick is wrong, or missing where an industry is correct.
- **none** — the entity shows a pick but should show no industry (industry NULL:
  a party, leadership, caucus, candidate or ideological committee with no
  sponsoring industry).
- **unsure** — the reasoning and the connected org disagree, or the call turns
  on a boundary only Craig can set.

The rules, in order:

1. **An existing override is a prior verdict.** Right, unless rule 4 below puts
   it in question. Then it is unsure and **not changed** (rule 45: no silent
   widening or narrowing of a curated cohort).
2. **A committee whose connected org is a corporation, union or trade group** →
   that org's industry. The rule tagger's keyword hit is the reference and is
   cited.
3. **A party committee (X/Y/Z), leadership PAC, caucus PAC, candidate committee
   (H/S/P), joint fundraising committee, or partisan super PAC / hybrid with no
   sponsoring industry** → no industry. No pick is right; a pick is `none`.
   Individuals are never keyword-tagged (FIX-437), so no pick is right.
4. **`lobby` is for lobbying firms and single-issue advocacy groups.** This is
   Craig's 10-03 call on the NRA PVF, recorded in
   `2026-10-03-fix1204-null-committee-overrides.tsv`: *"single-issue advocacy:
   firearms (Craig 2026-10-03); lobby is the industry — no secondary axis"*.
   Applied the same way: a group with one named cause (Israel, reproductive
   health, environment, gun safety) → `lobby`. A multi-issue or general partisan
   group → none. **Flagged for Craig:** the 07-27 audit curated 23 committees as
   `lobby / ideological_advocacy`. Under this reading the general partisan ones
   among them would be none. Three of them are in these populations
   (Progressive Turnout Project, VoteVets, 314 Action) and are marked unsure,
   not none. NextGen Climate would read `lobby` ("single-issue advocacy:
   climate"), but it is outside both populations (§4).
5. "Public knowledge" marks a verdict that rests on what a committee is rather
   than on a column here: UDP is AIPAC's super PAC, Fairshake is crypto-funded,
   Equality PAC is the Equality Caucus's PAC.
