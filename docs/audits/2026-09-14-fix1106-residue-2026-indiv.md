## 2. The premise it contradicts

FIX-1106's harness number is **3,416 recipients / 209,017 rows / $1,481,928,516**,
measured on prod 2026-08-25 **by the bracket-row proxy**, and described as
2,736 financial entities plus 680 officials.

Three ways it cannot be describing this slice:

1. **The slice has no financial entities in it at all.** Every one of the
   1,107,506 rows is `to_type = 'official'`, across 2,718 officials. A figure
   whose majority is 2,736 FE recipients is not a subset of a population with
   zero.
2. **3,416 recipients exceeds the slice's 2,718.** A residue set cannot be
   larger than the set it is residue of.
3. **$1,481,928,516 exceeds the whole slice's present value of $1,388,174,001.**

So this is not "the residue shrank by 93 % since August". The proxy and the
emit set are measuring different populations — the proxy almost certainly spans
all four FEC sources (`fec_bulk_indiv`, `_indiv_to_committee`, `_pac`, `_ie`),
where FE recipients do exist. **Rule 76 says the emit set is the exact
instrument; that is the reason to believe it and the reason not to reconcile it
against the proxy by adjusting the manifest.** The number that needs re-deriving
is the bullet's, not this one's.

## 3. The second, larger reason the apply must not run

The numeric gate would have been enough. This is worse.

**There is exactly one `fec_bulk_indiv` emit run in `fec_emit_runs`, ever** — the
one above. `fec_emit_keys` and `fec_emit_runs` shipped in cc-118; the two runs
before tonight (2026-09-12) never reached `complete_at`. So the emit set is a
**single observation**, and a single observation cannot separate:

- **(a) retraction** — FEC used to report contributions to this recipient and
  has stopped, so the standing rows are stale. This is what FIX-1106 is about
  and what DROPPED-OUT is supposed to mean.
- **(b) a standing match gap** — the pipeline has never resolved contributions
  to this recipient, the rows pre-date the emit instrument, and they are real.

The audit classifies both as DROPPED-OUT, because from one run they are
indistinguishable.

The evidence points at (b) for at least part of the set:

- **Susan Collins** — 3,248 rows / **$6,033,338** in the delete set. Sitting
  senator, Maine, **up for election in 2026**. FEC is certainly still reporting
  individual contributions to her committee. Her rows were all written in one
  51-minute window on **2026-07-27** (`min` and `max` `updated_at` 06:46:59 and
  07:37:00) and nothing has touched them since, and she has **zero emit keys in
  any cycle-2026 run of any source**.
- The DROPPED-OUT cohort as a whole has **no September writes at all**:

  | last write | DROPPED-OUT recipients | rows |

  | 2026-06 | 3 | 139 |

  For comparison, 8 PARTIAL recipients do carry September writes. The
  DROPPED-OUT set is a cohort that stopped being written in July/August and was

The context that makes (b) plausible rather than speculative: tonight's
fec-phase logged `FIX-937: 13189 of 32989 officials excluded from the

electable and so is not one of the 13,189 — but the run does have a

**Deleting the DROPPED-OUT class today would destroy $106.6 M of contribution
history on the strength of one observation, and at least one of the 128 rows is

## 4. What would make this decidable

Cheap, and none of it needs a decision now:

1. **A second complete emit run.** The next is the Sunday 2026-09-20 emitting
   run. A recipient absent from two consecutive complete emit sets, having been
   present in neither, is still ambiguous; a recipient present in one and absent
   from the next is a retraction. The instrument needs a baseline before its
   absences mean anything.
2. **Re-derive the bullet's number per-source.** Run the audit for
   `fec_bulk_indiv_to_committee`, `fec_bulk_pac` and `fec_bulk_ie` and sum. That
   is what the 2026-08-25 proxy was almost certainly measuring, and it is the
   comparison the bullet actually needs.
3. **Ask the narrow question directly for one recipient.** Does the current
   FEC `indiv2026` file contain contributions to Collins's committee? A yes
   turns the DROPPED-OUT class into a match-regression FIX and takes it out of
   FIX-1106's scope entirely.
