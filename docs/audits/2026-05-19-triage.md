## `officials.president_count` — audit-check bug + data gap → fixed in FIX-318

Current check: `is_active = true AND role_title ILIKE '%president%' AND role_title NOT ILIKE '%vice%'`.

Prod breakdown of matches:

| role_title | tier | n | has congress_gov |
|---|---|---:|---|
| Candidate for President | candidate | 2603 | false |
| SPECIAL REPRESENTATIVE OF THE PRESIDENT … | elected | 1 | false |
| PRESIDENT, SOUTHWESTERN INDIAN POLYTECHNIC INSTITUTE | elected | 1 | false |

The 2603 candidate rows came in with FIX-246's cn24.zip ingest (post-cutover).
With FED_FILTER (`source_ids ? 'congress_gov'`) applied, the count drops to 0 —
which is the second finding: **the sitting U.S. President is not in `officials`
at all**. No executive-branch ingest exists.

Decision: tighten the check to `tier = 'elected' AND role_title ~
'^President( of the United States)?$'`. Drops false positives to 0. The
remaining 0 actual vs 1 expected is a real data gap, filed as **FIX-321**
(executive-branch ingest).

## `officials.senators_per_state` — audit-check bug → fixed in FIX-318

Current check groups by `COALESCE(metadata->>'state', metadata->>'state_abbr')`.
Prod query of the 100 active federal senators shows `metadata` is literally `{}`
(empty JSON object) — there are no top-level metadata keys. The `state` and
`state_abbr` paths both return NULL for every row, so all 100 fall into the
NULL bucket and the check flags "1 state ≠ 2".

The actual state info lives via the JOIN `officials.jurisdiction_id →
jurisdictions.name`. Confirmed all 50 states show exactly 2 senators when
joined that way (Alabama: 2, Alaska: 2, …, Wyoming: 2 — all 50 ✓).

Decision: rewrite to `LEFT JOIN jurisdictions j ON j.id = o.jurisdiction_id`
and `GROUP BY j.name`. Eliminates the false positive.

The actual prod metadata key for senator state is **none — it lives in
`jurisdictions.name`, not in `officials.metadata`**. Worth updating the
memory note that assumed `metadata->>'state'`.

## `officials.rep_count` — real data gap → filed as FIX-321

Current check: `COUNT(*) WHERE role_title ILIKE '%representative%' AND
source_ids ? 'congress_gov'`. Returns 438; expected 441 (435 voting + 6
non-voting delegates).

Prod breakdown:
- All 438 are `role_title = 'Representative'` (no other shapes).
- All 438 have `source_ids ? 'congress_gov'`.
- No rows match the delegate role-title patterns (`%delegate%`, `%resident
  commissioner%`, `%non-voting%`, `%nonvoting%`) — so delegates aren't
  shaped distinctly.
- Jurisdiction breakdown shows the 50 states totaling 432 + jurisdiction
  `"United States"` carrying 6.

Most likely interpretation: the 6 reps mapped to the `"United States"`
jurisdiction are the 6 territorial delegates (DC, GU, AS, MP, PR, VI) that
landed in the umbrella jurisdiction rather than their territorial ones, plus
3 House seats are vacant (435 - 432 = 3).

This is option (a) + (b) from the triage prompt's bucket framing —
3 vacancies AND the delegate-mapping shape needs investigation — not option
(c) "audit check matching wrong". So FIX-318 leaves the rep_count check
shape and `expected=441` untouched; the gap is filed as part of FIX-321
(officials ingest completeness).

If the delegate-jurisdiction mapping is fixed without filling the
vacancies, the count would still report 438 (no behavioral change). If
vacancies are real and accepted, the check's expected might want to flex
to "≥ 435 voting reps + 6 delegates accounted for", but that's a FIX-321
follow-up decision, not a FIX-318 one.

## `proposals.procedural_contamination = 1865` — real data regression → filed as FIX-319

Sample shows civil-case titles (`Kaur v. Blanche`, `Vanicek v. Blanche`,
`Crew v. Ratliff`) and Seattle / SF municipal proposals (`Appointment of Todd
V. Biesold as member, Seattle Freight Advisory Board`, `Ordinance authorizing
settlement … Linda Kay Roberts v. City and County of San Francisco`) leaking
into `proposals`. The check pattern is `title ~* '^on ' OR title ~* ' v\\. '`,
which is matching real court-case names that the source pipelines should be
filtering out.

The check is correct; the regression is upstream in the proposal pipelines
(courtlistener? legistar? regulations-gov?). Out of scope for FIX-318; filed as
**FIX-319**.

## `referential.orphan_entity_tags = 170` — real data regression → filed as FIX-320

170 `entity_tags` rows with `(entity_type='financial_entity', entity_id)` that
don't resolve to any `financial_entities` row. Most likely fallout from FEC
bulk pipeline re-runs that recreated `financial_entities` rows with new UUIDs,
orphaning the old tag rows. The check is correct; cleanup + ingest fix is
out of scope. Filed as **FIX-320**.
