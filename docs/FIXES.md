# FIXES — Civitics Platform

Actionable improvement backlog. Every item has a priority, complexity, and enough context to hand to Qwen or Claude Code directly.

**Priority key:**
- 🔴 Critical — Bug that breaks or blocks real functionality
- 🟠 High — Meaningful product/UX gap, address soon
- 🟡 Medium — Worthwhile improvement, schedule when practical
- 🟢 Quick Win — Small effort, high visible impact (batch these)
- ⬜ Future — Phase 2+ or requires significant design/pipeline work

**Complexity key:** S = <2h · M = 2–8h · L = 1–3 days · XL = multi-day + planning

**Workflow:** Every bullet has a stable ID (`<!--id:FIX-NNN-->`). Don't remove or renumber IDs — they're the handle commits reference via `Fixes: FIX-NNN` trailers. Completion state is sourced from `docs/done.log`; regenerate this file's checkboxes with `pnpm fixes:sync`. See [CLAUDE.md](../CLAUDE.md#fixes-workflow) for details.

**Section rules:**
- Active sections — `[x]` items are fine (checked by `fixes:sync`). Periodically move completed clusters to `## COMPLETED` for readability.
- `## COMPLETED` — **`[x]` only**. A `[ ]` item here means it was moved before it shipped — move it back to the active section.
- Deferred / blocked items always stay in active sections as `[ ]`, never in COMPLETED. If a deferred item was closed by a broad "closeout" commit, add a `reopen` line to `done.log` and uncheck it.

- [ ] 🟠 M — **A bulk landing must PRE-DRAIN the derived-layer debt it creates, in the same quiet window — not leave it for the next scheduled firing** — STANDING CONVENTION, proposed. The 2026-08-19 saturation is the cleanest instance yet of a repeating shape: a bulk write lands cheaply and hands an unbounded bill to whatever derives from it. The FEC same-person merge and re-split work bulk-rewrote financial_relationships; that rewrite bumped updated_at on ~70 percent of all donors; the EC incremental donations arm is watermark-driven, so its dirty set went from a normal few thousand to 3,357,701 rows over 1,961,194 from_ids; and the next scheduled firing spent six hours on it, wrote zero, and took the request path down with it. NONE of that cost appeared in the landing script. It appeared two days later, in a different job, at 08:00 UTC on a weekday, with no operator watching. THE RULE: a script that bulk-rewrites a table owns the derived-layer work its rewrite creates, and drains it in the same quiet window, before it exits. This is the exact sibling of the vacuum rule already standing in CLAUDE.md — any script that bulk-rewrites a table ends by vacuuming what it rewrote (FIX-943) — and it comes from the same failure: the cost is real, it is created by the landing, and leaving it to a background mechanism means it lands on a schedule nobody chose. Vacuum debt and derived-debt are the same category of unpaid bill; the vacuum half is already a written convention and the derived half is not. WHAT PRE-DRAINING MEANS CONCRETELY: after the bulk write and its vacuum, the script drives the derived arms its rewrite dirtied to convergence — for a financial_relationships rewrite that is the EC donations arm and the donor rollup — rather than assuming the weekly cron will absorb it. Post-[[FIX-1069]] this is cheap to do safely, because the donations arm is now 16 committed, budget-checked, resumable windows that can be driven to convergence and re-entered if interrupted. AMENDS THE PR 3b DISPATCH RECIPE: 3b lands per-cycle FEC replays, which is precisely a repeated bulk rewrite of financial_relationships. Its per-cycle dispatch recipe should gain a post-cycle derived-drain step so cycle N pays its own derived cost before cycle N+1 starts, instead of accumulating debt across cycles for a Monday firing to discover. The 3b sessions consume this bullet; it is NOT a request to rebuild the [[FIX-974]] bulk-regime pass here.
