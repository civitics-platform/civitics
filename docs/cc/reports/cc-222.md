## 5. What contradicted the prompt

- **The candidate-stub writer is not `fec-bulk/writer.ts`.** Stubs are inserted
  in two places:
  - `fec-bulk/candidates.ts:311-333` (cn), which sets `fec_election_yr`,
    `cycle`, `cand_status` and others.
  - `fec-bulk/mint-ie-targets.ts:205-223` (IE), which sets only `state`,
    `source` and `fec_office`, with **no election year**.

  8 of the 46 stubs are IE-minted. For five of them the terms or the letter
  decide the class anyway: Cassidy, Markey and Cantwell are A1, and Ivey and
  Gillen are C. Webster and Ossoff are undecided; see the D bullet below.
  Warner is D because his id is a `P`.
- **"Every read < 1 s" did not hold.** The batched 46-stub FR read had an
  estimated 27,324 rows and an actual 85,007 rows, heap-read cold. It was
  cancelled at my own 30 s `statement_timeout` guard, not by the server's.
  I split it into one call per stub, which took 0.37–6.6 s each. The collision
  probes took up to 17 s (John James). Everything was EXPLAINed first where it
  was not a single-id lookup.
- **Two claimants:** no row's `reason` names two.
- **Elected or bioguide stubs:** none. All 46 stubs are `tier='candidate'` with
  no `congress_gov`. They are all `is_active=true`, but both writers set that on
  every stub, so it is not evidence of anything.
- **Rows the dataset terms do not decide:**
  - **A2** (John James, Bell): the terms show no Senate term, and the cn stub's
    `fec_election_yr` (2020, 2024) decides it. That is the prompt's second
    disjunct. These are prior candidacies, never prior offices; flagged as §5 Q2.
  - **B** (all 17): the terms say only "no Senate term". "Concurrent" rests on
    `fec_election_yr = 2026`. Two of them, Norman and Fry, have FEC
    `cand_status N` (not yet a candidate).
  - **D** (Webster, Ossoff): both stubs are IE-minted and carry no year. The FEC
    cn record for each id (`CAND_ELECTION_YR`, `CAND_STATUS`) would decide them,
    and this audit did not read it.
- **The gate's other-chamber check is a letter inequality.** It would accept a
  `P` id (Warner) and every class-B row whose first names agree. The prompt
  anticipated this for class B; the `P` case is new.
- **The collision rule is the finding the prompt did not ask for.** The
  Luján-precedent framing "Σ conserved" means conserved **net of** the losers
  the fresher-row rule deletes. The FIX-933 premise behind that rule is "same
  FEC data under two bindings". Here each pair is two different CAND_IDs, so two
  committees, and the writer sums such a pair when both ids resolve to one
  official (`writer.ts:992-1011`).

  | class | colliding rows | losers | of which "live-both" |
  |---|---|---|---|
  | A | 4,410 | $22.18M | $8.72M |
  | B | 22,467 | $41.86M | $14.20M |

  "Live-both" means the survivor's row was refreshed after the stub's row was
  first written, which is a heuristic. Cron re-emits indiv for the active cycle

  pass and a 2020–2024 loss does not.

  Some IE collisions are equal to the cent on both sides (Rosen, Gillen), which
  makes them true duplicates that are double-counted platform-wide today.
