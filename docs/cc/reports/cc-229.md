## The four questions

1. **Upstash:** three crawl bursts that skipped Cloudflare spent the limiter's 500k
   allotment: 357k commands in the bursts against a baseline of ~140 per 30 min. Writes
   stopped landing at ~20:30–20:32Z on 10-12.
2. **Vercel:** the same ~445k requests reached the Vercel origin directly. The snapshot
   shows the 10-11 billing day at +49,414 invocations, 2× the day before. The 10-12 day
   lands at ~07:00Z on 10-13.
3. **Restart:** the postmaster restarted at **04:11:32Z**, not 03:53Z. 03:53Z is when the
   killed `platform-counts-daily` run started. Burst 2 had pushed a box that started near
   its swap ceiling to swap 1,023/1,024 MB. It was **not** the front-door arm: `action:
   none`, `down_ticks: 0`, only one RED bucket. Expect no front-door mail.
4. **Tail:** `ai-summaries`' supabase-js work-list read on `proposals` hit the service_role
   8 s statement timeout. The cause was not Anthropic (queue mode) and not a kill switch.
   The read is indexed and passed the prior nights, so this was a transient on a box still
   swapping, not a code bug. No FIX.

## Standing risk until the quota resets

- **The front-door auto-restart is disarmed.** Two paths lead there: an unreadable store
  gives decision `none`, and a readable store still cannot advance the hold, because the
  hold is an `INCR` (a write) and writes are what fail over quota.
- **The rate limiter is per-instance memory.** This is fail-over working as FIX-1038
  designed.
- **The off-box memory ring is dark.** The on-box mirror and `box_is_saturated()` are
  unaffected.
- **Receipts memory windows do not bank.** For cc-219's verifier: the ring still holds
  10-11 21:00Z → 10-12 20:30:22Z, and a retried read lands.

**When the reset comes is itself unsettled.** The tree (FIX-1089) says 10-13 ~07:51Z.
The only observed reset, `healthy` at 09-01T00:01:16Z, points to 11-01 00:00Z. Watch
`upstash_limiter_health`.
