## What contradicted the prompt

1. **The delta's redirect code was an open redirect.** `new URL(pathname + search,
   "https://www.civitics.com")` with a pathname of `//evil.com/x` resolves to
   `https://evil.com/x`. The local smoke showed that Next's own server normalises
   `//` to `/` before middleware runs (`location: /evil.com/x`, which is Next's
   redirect, not ours), so this probably was not reachable. I fixed it in the helper
   anyway and tested it, rather than relying on that normalisation.
2. **The platform-snapshot check is weaker than §9 implies.** In report mode, a
   request through Cloudflare that the Transform Rule failed to stamp is still
   served 200, so the GHA probe stays green whether or not the rule works. Read 1's
   (c) is only proven by cc-231's log read: zero `cf-ray=yes` misses. A `cf-ray=yes`
   line is cc-231's STOP signal.
3. **`/wp-*` never reaches middleware.** `next.config.mjs` redirects those paths
   (307 to `/404`) before middleware, so they carry no `miss` stamp. This was already
   the case, and it is harmless. Middleware's own `BOT_PATTERNS` 404s are stamped.
4. **The secret header is forwarded to route handlers.** `NextResponse.next({
   request: { headers } })` passes `x-civitics-origin` through unchanged. No route is
   known to echo headers back, but stripping the header before forwarding is cheap
   defence in depth. It is a candidate for cc-231, not done here.
5. **Read 3's count.** `vercel.json` has 9 cron *entries*, and there are 9 route
   *files*, but they are different sets. `vercel.json` schedules gha-dispatch three
   times (nightly, sync-canary-check, platform-snapshot) and no longer schedules the
   status/usage halves (cc-216's revert). All 9 files are gated either way.
