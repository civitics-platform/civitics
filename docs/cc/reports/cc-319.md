- **D2: the DELETE runs behind an `EXISTS`.** `data_flags` grants

  cleanly as `service_role`, so an unconditional DELETE would have made every
  `service_role` promotion raise. Behind the `EXISTS` it raises only on a real
  collision. The one live caller connects as `postgres`. No grant changed.
  Widening `data_flags` to DELETE is Craig's call if a `service_role`
  promotion path ever matters.
- **D2: no re-point statement.** Read 3 found 0 orphans.
- **D3: `CREATE OR REPLACE TRIGGER`, not `DROP … IF EXISTS` + `CREATE`.**
  DROP TRIGGER takes ACCESS EXCLUSIVE on `votes` even when nothing exists to
  drop, which blocks every reader. `CREATE OR REPLACE TRIGGER` (PG 14+) takes

  (named, under `lock_timeout` 5 s).

  restore on every fired row. Every name is qualified and the function is
  SECURITY INVOKER.
- **D3: the queue grants `service_role` SELECT, INSERT and DELETE.** The
  trigger runs as the vote writer, and the legistar writer upserts as
