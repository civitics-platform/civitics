## Decisions changed, and why

- **D1, reason text.** A single item that is not recognised used to read ``after `X` is not a date or a zoned ISO instant``. It now reads ``…is not cc-<n>, a date or a zoned ISO instant``, because `cc-<n>` is now a legal item. The catch-all reason names the new form too. No assertion read either old string (grep). Today's `after <ISO>` *result* is unchanged apart from the new `deps: []`, which the §6d deep-equality case now pins.
- **D2, values the prompt left open.** For a window, `opens_ms` = the window's start. For `none`/`any`/`at` it is `null`. A dependency whose report has no readable `finished_at` counts as met, because D3 makes a report existing the whole signal, but it adds nothing to `opens_ms`. If nothing else gives a time, `opens_ms` is `null` and the board pill reads plain `ready`. The `reason` strings are mine: `waits on cc-N[ · not before <ISO>]`, `not before <ISO>`, `cc-N reported · ready since <ISO>`, `open since <ISO>`, `not open until`/`open until`/`closed at <ISO>`, `any time`, `planned for <ISO> (an at is a plan, not a bound)`.
- **D3: `git show` instead of `git cat-file -e`.** `checkoutReportFinishedMs` reads the checkout's `reportsDir` first, then `git show origin/main:docs/cc/reports/cc-<n>.md`. One call answers both whether the report exists and what its `finished_at` is, and the script never fetches.
- **D6: no nulls in `board.json`.** `test-board.mjs` already asserts that `board.json` contains no `null`. The card's `when_status` therefore leaves out `opens_ms` when it is null rather than writing `null`, and a `none` card has no `when_status`, as in `cc:prompt`. When a met card's `opens_ms` is unknown, its prod day is today, and its week event is today with the label `ready`.
- **D6: fixtures built in memory.** Writing 909–912 as fixture files would change the expected text of the existing `every numbered prompt is listed` assertion, and the STOP table forbids editing old cases. So §6d'' builds a second board from `{...inputs, prompts: [...inputs.prompts, ...four]}`. All existing assertions run unchanged against the original tree.
- **D4:** `--anyway` without `--start` does nothing. A refusal prints to stderr, the same as `ABORT`.

## The next prompt: what a dependent `when:` still cannot say

1. **"After FIX-NNN's prod receipt."** A dependency is met when a *report* exists. A report that FAILs `cc:verify` still counts, and so does one whose prod step is still owed. A prompt that needs cc-317's push to have reached prod still needs a Phase 0 read with a STOP row.
2. **"Either of two."** Every dependency must be met. There is no OR.
3. **"After cc-317 but before 04:00Z."** A dependency cannot be combined with a window. The one allowed instant always means *not before*. A prompt that must finish before a nightly still has to state that in its STOP table.
4. **Freshness.** `cc:prompt` reads `origin/main` as of the clone's last fetch. A dependency that reported since then reads `waits on` until someone runs `git fetch`. `session:check` pulls the primary at session start, and the ref is shared across worktrees.
