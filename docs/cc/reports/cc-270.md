## What contradicted the prompt

- **`fixedWindow`'s cost in v2.0.8.** As the prompt said: EVALSHA + INCRBY, plus PEXPIRE on a key's first check, so 2 / 3 commands. The same `(tokens, Duration)` signature as `slidingWindow` (`index.d.ts:694`). Both algorithms name keys `<prefix>:<id>:<floor(now/window)>`, which is why the `:fw` prefix matters.
- **But the −48 % is out of date.** It assumed the census week's 13 % first-in-window share. 11-10's sliding k is 5.15, so the fixed-window saving is nearer −40 % (k ≈ 3.15). The owed k receipt carries both bounds.
- **The test cases.** `ratelimit.test.ts` has 3 `windowMs` cases (9 assertions), not 12, and none pinned the algorithm. All 46 behaviour cases passed unchanged. New cases: the algorithm per bucket, the `:fw` prefix, `client-ip.test.ts` (3) and `limiter-health-route.test.ts` (3, source-anchored). The app suite is 491/491.
- **`client-ip.test.ts` is 3 cases, not 3 × 3.** The `enforce` / `report` / `off` matrix belongs to Item 4, which did not land.
- **The edge-runtime import.** `ratelimit.ts` imports fine on the edge, but D3's premise that the route shares the middleware's isolate is false. Next 14 bundles middleware and edge routes separately (middleware-manifest), and prod returned `mode null` and all zeros. To serve FIX-1304, the middleware would have to answer `/api/cron/limiter-health` itself. That is a design call for Cowork.
- **The favicon tooling.** Neither `sharp` / `png-to-ico` nor `@resvg/resvg-js` is in the lockfile, and the scratch install was denied. The icon is two primitives, so it was rasterised exactly with Node built-ins: 16× supersampled coverage, 32-bit BGRA DIB entries.
- **The favicon files.** `icon.svg` is `app/icon.svg` (the App Router file convention, which already emits `<link rel="icon">`), not `public/icon.svg`, so `metadata.icons` was not added.
- **The matcher DOES exclude `favicon.ico`** (`middleware.ts:467` after this run; `:475` before), contrary to the prompt's read-0 note. That is why the favicon cost 0 commands.
- **The favicon's Cache-Control was set pre-emptively.** Vercel serves `public/` with `max-age=0`, which would have forced a second deploy. The header rule shipped with Item 3 instead.
- **The GraphQL filter names.** `originResponseStatus_gt` and `clientRequestPath_like` were accepted as cc-269 used them.
- **cf-analytics.mjs header.** It never carried a "cannot join UA × path" claim — that was the cc-269 prompt's — so there was nothing to drop.
- **Git Bash rewrites a leading-`/` argument into a Windows path** (`"/favicon%"` → `"C:/Program Files/Git/favicon%"`). That silently matches nothing. `--path-like` now refuses a value that doesn't start with `/` and names `MSYS_NO_PATHCONV=1`.
