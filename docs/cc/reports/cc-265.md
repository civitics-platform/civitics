## What contradicted the prompt

1. **D2's "upper bound" is backwards, so read 2's rule cannot decide.** `pgmajfault` counts faults and `pswpin` counts pages, and two things follow:
   - One fault can read many pages. That is in the data: pswpin ran 1.84× pgmajfault, which one page per fault cannot do. So faults × 4 KiB is a floor on bytes.
   - Swap-in faults are in `pgmajfault` too, so it is not a file-only number, and the premise "major faults, never `pswpin`" is half wrong.

   The numbers are computed as D2 specified. The header, the README and the §9 line say floor, and the §9 clause is labelled a hypothesis.
2. **One release attempt was not enough.** The event that kills the lock should refuse the next connection too, so a single try would fail on the very event this fixes. I added the 60 s retry. This is reasoned from how Postgres shuts down, not measured on prod: cc-255's first poll came after the restart. Locally the first attempt connects, because the server stays up.
3. **`releaseOnSignals` did not gain an error path.** It lives one level down in `claimProdSession`, so `withProdSession`, the CLI and any other claimant all get it. The signal path is unchanged and green.
4. **pg emits `error` twice on a FATAL,** the FATAL and then the socket close. A `once` listener would have crashed mid-release, so the listener stays attached. `withClient`'s short-lived client had no listener either, so a backend killed under it ended the process. It has one now.
5. **My first draft could hang the exit.** The lost path awaited `lock.release()`, which on the ticker's half-open client would query a dead socket and never settle. I took the call out before committing; the exit closes the socket.
6. **"Disjoint files" did not make the local DB disjoint.** cc-264's five migrations reached the shared clone before their tests were in my tree, so my first three proof runs each failed 30 cases on its routines, r9 included. They say nothing about the race, and the STOP table's `lockName` alternative did not apply. I waited 13 min for its landing and reran. A concurrent pair where one side migrates cannot run clone proofs until that side lands.

8. **The baseline was 0 / 2 / 1,** not 1–3 per run. The first run was clean.
9. **`concurrent_with: [cc-264]`:** `cc:prompt` flags it (`not cc numbers — cc-264`). The shape is `[264]`.
10. **FIX-1388's owed receipt reads less than it sounds.** CI has no DB, so the clone cases skip there. It proves the runner, and the race's proof stays local. CI's log shows both passes.
