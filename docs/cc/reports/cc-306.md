## What contradicted the prompt

1. **The FIX-1434 owed look does not reach the route.** In-repo, nothing calls
   the default view: both `/api/graph/connections` fetches in
   `useGraphData.ts` (:321, :495) pass an `entityId`. `/graph` with no entity
   renders the empty state and makes no connections request. I saw this on
   local with the old hook, where the page landed on the empty state and fetched
   nothing. So the default view is reached only by a direct GET (a crawler, a
   probe, a hand-typed URL). I rewrote the owed `what` to that direct URL. The
   fix still stands, because a public route that 500s on a cold cache is a
   500. Read 0's STOP row did not fire: nothing reads `count`.
2. **Read 1: a stored total exists.** `platform_counts` has the row
   `metric = 'entity_connections'`. `refresh_platform_counts()` writes it daily
   from `pg_class.reltuples` (FIX-1376, `method = 'estimated'`; on local,
   6,938,779 at `2026-11-20 03:53Z`). I used the live `estimated` HEAD instead,
   which D1 allows. Both read `reltuples`. The HEAD is as fresh as the last
   analyze rather than a once-a-day copy, costs about 25 ms, and adds no
   dependency on the daily procedure.
3. **Read 2's premise of "tens of ms against seconds".** Warm, the exact count
   took 615–627 ms, not seconds. Cold, it never finished: 500 at 8.1 s. How long
   an exact count takes depends mostly on how much of the table is cached.
   `select=*` is the worst projection for it: a cold `select=id&limit=1` GET
   took 3,852 ms. The estimate is flat at 24–65 ms either way.
4. **The graph package has no test runner in CI.** As
   `graph-vote-tier.test.ts` already does, the FIX-1435 test lives in the app
   suite and imports `packages/graph` by relative path.
5. **A local A/B trap, worth a Playbook line.** `next dev` serves unhashed
   chunk URLs (`/_next/static/chunks/app/graph/page.js`) with
   `Cache-Control: public, max-age=31536000, immutable`. A browser profile that
   reuses one cache runs whichever chunk it cached first. My first "old line"
   page check ran the already-fixed chunk and looked like a refutation of
   read 3. Running `Network.setCacheDisabled` over CDP (or using a fresh
   profile per run) gave the real result.
6. **Estimate caveat, not acted on.** FIX-1095 recorded that `reltuples`
   overstated `votes` by 31% after a bulk delete. `entity_connections` also
   gets deletes: per-source stale-closes, and the rebuild. A large delete would
   overstate this count until the next analyze. Nothing displays it, so this is
   only on record here.
