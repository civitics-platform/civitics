## 3. What contradicted the design or this prompt

1. **`parseFrontMatter` carried `owed` unchanged.** No parser edit was made,
   and the 45 sidecars are md5-identical before and after. D1's inline-map
   shape is what shipped. `after` is required and must carry a zone. A
   zoneless `2026-09-29T15:00` FAILs, because the board renders in UTC and
   a local instant would shift by the writer's offset.

2. **The window reaches cc-126, not cc-162.** `finished_at ≥ now − 14 d` is
   2026-09-14T04:05Z, which takes in 44 reports. The backfill map covers
   162–170, and the out-of-scope list forbids going earlier. The rule that
   every report sits in exactly one lane therefore needed a sixth place: a
   **"no lane" strip** under the lanes. It is 36 cards today, and it drains
   by itself as the window rolls forward to about 2026-10-12. No shipped
   report needed the backfill map for any reason other than age.
   - cc-169 has **no report**. It is a drafted prompt (Tuesday's receipts).
     Its backfill entry places the prompt card in ops.

3. **"Every prompt with no report" would be 126 cards.** The prompts folder
   holds 186 numbered prompts. cc-1…121 and the FIX-numbered ones (`468`,
   `497`, `499`, `500`, `573`, `677` ×2, `678`, `945`) have no report
   because they ran before reports existed. The board shows a report-less
   prompt only when:
   - it carries front matter (the cc-171 shape), or
   - it has a `.running` marker, or
   - it is a legacy prompt whose number lies between the lowest cc in the
     window and the highest report cc.

   That admits cc-169 and cc-171 and skips 124. `cc-prompt-677` also has
   two files. `cc:prompt 677` refuses it as designed. The board flags such
   duplicates, but none falls inside the range.

4. **Cron expansion on the real `cron_jobs`.**
   - Among the non-daily jobs, **no `*/N` field occurs**. The `*/N` jobs
     (`box-health-probe`, both watchdogs, `ec-crawl`, `fe-crawl`) are daily
     class, and they are among the 26 not drawn.
   - The five day-of-month jobs, `1 * *` (jobids 23, 14, 15, 18, 19), fall
     on **Thu 10-01**, inside the week.
   - **No cron job went to `later`.** The only `later` event is the
     congress-ids gate.
   - The four inactive non-daily jobs (16 `entity-connection-stats-rebuild`,
     13 `financial-entity-totals-incremental`, 2 `rebuild-ec-incremental`,
     22 `rebuild-ec-incremental-mon`) are **not drawn**. They are listed in
     the page footer, because drawing a job that will not fire would be
     worse than omitting it.
   - The fixture covers `*/15 * * * 1`, which is drawn once on its next
     occurrence with its schedule in the label, and `0 12 15 * *`, which
     goes to `later` with its date.

5. **`/cc` Step 1 needed no change** to read a prompt that opens with `---`
   (read 5). `cc:prompt` exists for the D4 abort and the marker.
   - The cc-171 marker itself was written by hand at 03:43Z, because
     `cc:prompt` did not exist yet.
   - It is removed by `pnpm cc:prompt 171 --done` after this report is
     pushed.

6. **The board's "verify" is `verifyReport`, not a `cc:verify --json`
   subprocess.** It builds one batched context with no `git fetch` and no
   `gh`. So `ci: green` is UNCHECKED on the board. That keeps the output a
   function of the tree and `--now`, not of whatever the latest CI run
   happens to be. Without it, a red main would flip every historical report
   to "verify FAILs". It also keeps the render at about 2 s instead of about
   40 git spawns per report. `pnpm cc:verify <n>` still cross-checks CI.
   The context is `buildVerifyContext()`, now shared by the CLI and the
   board.

7. **Links, and where the local file lives.** Report and plan-file links
   point at the **primary** checkout's copies, so the page is byte-identical
   whichever worktree rendered it. The primary checkout is the human view.
   `.claude/board.local.json` is read from the primary checkout for the same
   reason. It does not exist on this machine yet, so there is no footer row.
   `docs/cc/board.local.example.json` has the shape with `HH:MM`
   placeholders.

8. **`buildUniverse` moved** from `fixes-status.mjs` into
   `lib/fix-status.mjs`, and `fixes-status.mjs` re-exports it. Importing
   the CLI ran `git rev-parse` at load and crashed under `node -e`.
   `fixes:status --json` gives byte-identical output, old code against new.

9. **Rule 212 gap.** `fixes-integrity.yml` runs `test-cc-verify.mjs`, which
   now also covers `cc:prompt`, but not `test-board.mjs`. So `board:test`
   is local-only through `fixes:test`. It would be one more workflow step,
   pure Node and about 0.5 s. I did not file it. Cowork can decide.

10. **In the reference render but not derivable from the tree.** Drop these
    from the design rather than have the board invent them:
    - **"verify" calendar events** ("verify cc-166 · 167 · 168 reports").
      There is no dated "report lands" event. Verification happens at
      render time.
    - **Cowork calendar events** ("write the FIX-1012 drop prompt"). Only a
      `kind: design` plan step with an `after` becomes a design event.
    - **Queue cards for work in no plan file.** The queue is plan steps
      only. These all fall outside it:
      - FIX-1012, P1-A backoff, box Small → Medium, FIX-1211, FIX-1145,
        FIX-1205, FIX-1203 · 1188, FIX-1186
      - `pnpm fixes:clean`, Actions secrets, seed-backlog cost, rules
        149–168, 1216's siblings
    - **Card prose.** "Δ open", "deadline", "prod: migration + pg_cron row",
      "verify when it lands: …", and conditional chips such as "CIC if clone
      wall × 1.4 > 180 s". These live in prompt prose, whose parsing is out
      of scope.
    - **Tile prose**, such as "gate: …" and "receipts: …". It lives in the
      plan file's free prose, not its front matter.
    - **The `officials-redesign` tile.** It has no plan file.
    - **A live "held by cc-165 · running" interlock.** The board shows the
      receipt's hold, which is as of the nightly.
    - **"collected Tue by cc-169"** on the owed badge.
    - **Meaning attached to cron events** ("jobid 17 crawl branch → FIX-969
      receipt", "weekend nightly; FEC drop possible"). The board shows job
      names and one uniform nightly label.

11. **Presentation choices, not in the design.**
    - Closed cards render collapsed (`<details>`), with every field one click
      away. With 44 reports in the window, open cards would bury the ones in
      flight.
    - A closed card keeps its `STOP ×n` chip but not the red border.
    - The owed badge counts receipts and reports separately.
