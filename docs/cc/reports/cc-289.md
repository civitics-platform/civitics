**Decisions I made that the prompt left open, or narrowed:**

- **D1 is offered to adopted pairs only** (`cls = adopt-prior`), not to every
  pair in a `--adopt-prior` run. A pair whose survivor already claims the id
  keeps today's refusal, where "both ids" would collapse to one. The dataset is
  read once, before the merge transaction, through O1's own `fetchFeed`. A
  failed read stops the run.
- **D2's classifier is the one implementation, in TypeScript**
  (`adopt-prior-rules.ts`). It reads microsecond timestamps from SQL, because a
  JS Date would round to milliseconds. Its verdicts land in a
  `_collision_class` temp table. The `_collision` CTAS and both loser DELETEs
  are byte-identical to `de65d66`, and a test pins that.
- **A live collision of a type the writer does not sum throws.** None exist in
  class A. A stale one of any type keeps today's rule. `donation_duplicate` is
  reachable only if `DUPLICATE_BAND_BP.donation` is changed.
- **Fields the writer's merge does not define keep the survivor's value:**
  `source_url`, `started_at`/`ended_at`, `created_at`, `fec_filing_id`,
  `is_in_kind`, `is_bundled`, and every metadata key except `tx_count`
  (`fec_committee_id`, `source`, `support_oppose`, `aggregated`, …). The writer
  itself keeps the *first* input's committee. On a `started_at` row,
  `occurred_at` stays NULL because of the table's CHECK.
- **`updated_at`.** The table's BEFORE UPDATE trigger stamps `now()` on a summed
  row, exactly as it does on a moved row. That bump is also what lets the
  incremental EC donations arm re-derive the survivor's edge. Survivor edges
  whose evidence included a deleted survivor-side row stay stale until that arm
  or `rebuild-entity-connections.yml` runs. That is today's behaviour.
- **D3 widened the money check** from donations only to donation, ie_support and
  ie_oppose, per type. An `ie_duplicate` loser is IE money, so a donation-only
  check could not hold it. The trio revert's return became per type to match.
  That is the one touch to another mode's code, and it changes accounting only.
