## §1 The table as built, the replays, the jitter test

`decideRestart` (`packages/db/src/front-door-restart.ts`) applies these rules in
order. The first rule that matches decides:

| # | condition | action | reason |
|---|---|---|---|
| 0 | not a Logs-arm DOWN | none | `front door not DOWN (<state>)`, or for a probe-only DOWN `DOWN on the direct probe alone — the hold counts Logs-arm DOWN ticks only (probe dark)`. The caller DELs `down_ticks down_since would_restart_sent` |
| 0b | Upstash read failed | none | `state store unreachable (…) — fail safe, no restart` |
| 1 | `downTicks < 4` | none | `DOWN tick N of 4 — the hold is 4 consecutive DOWN ticks (since HH:MMZ; probe answered\|dark)` |
| 2 | last restart < 60 min ago | skip | `last restart N min ago — spacing 60 min (DOWN tick N, since …; probe …; health …)` |
| 3 | ≥ 2 restarts in 24 h | skip | `cap 2/24 h — …` |
| 4 | mode `off` | none | |
| 5 | `report`, or `arm` without the token | would_restart | |
| 6 | otherwise | restart | `restarting — DOWN tick N, since …; probe answered\|dark; health …` |

How the count is kept:
- `countDownTick(verdict, stored)` gives `logsDown = state === "down" &&
  red[2] && red[3]`, and `downTicks = logsDown ? stored + 1 : 0`.
- The planner then writes `INCR down_ticks`, plus `EXPIRE … 86400` and `SET
  down_since … NX` on the first counted tick, or `DEL down_ticks down_since
  would_restart_sent` on the first tick that does not count.
- `MGET` reads five keys, `down_ticks` last.
- `downSinceMs` now feeds only the reason's "since" and `downForMs`.
