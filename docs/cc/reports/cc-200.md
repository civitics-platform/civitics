## 4. What contradicted the design

- **The clone does not mirror prod's promotion.** The prompt said "the
  survivors exist on the clone too", and they do. But so do all eleven OLD
  ids, because cc-194 W1 ran on prod only. The prompt's `WHERE EXISTS
  (survivor)` backfill would have written 11 redirects that 308 a live elected
  page to its candidate stub on local. I added `AND NOT EXISTS (old)`, which
  is the table's invariant: never redirect an id that still answers. With it,
  the clone holds 0 and prod holds 11. This also changed the local 308 proof
  to the prompt's "seed one row by hand" branch.
- **The edge fetch works as written.** `apikey` and `Authorization: Bearer
  <sb_publishable_…>` were both accepted by PostgREST, locally and on prod. I
  **did not depend on `AbortSignal.timeout`**: the module uses
  `AbortController` plus `setTimeout`, which every edge runtime has, and a
  test proves the timer really aborts a hung fetch. So whether Next 14.2.35's
  edge runtime has `AbortSignal.timeout` went untested, and it no longer
  matters. Nothing in `next.config.mjs` or Cloudflare needed to change,
  because the fetch goes to `xsazcoxinpgttgquwvuf.supabase.co`, not
  civitics.com.
- **Cold-isolate latency was not isolated.** The first 308 after the deploy
  (04:22:54.669Z) came from a polling loop that recorded status but not
  timing. The next two 308s took 362 ms and 165 ms end to end from here
  (pdx1), against a 365 ms direct anon PostgREST read from the same machine.
  The 362 ms one may have been a fresh isolate paying for the list read; I
  can't tell from the outside.
- **The `location` header is path-only** (`/officials/893a581e-…`), not
  absolute. Next's middleware adapter relativizes a same-origin redirect.
  Browsers and crawlers resolve it against the request URL, so the host is
  preserved as intended. curl here speaks HTTP/1.1, so the status line is
  `HTTP/1.1 308`, not `HTTP/2 308`. Neither 308 carried `x-vercel-cache`:
  middleware answers before the CDN cache.
- **CREATE OR REPLACE kept the ACL** (postgres plus service_role EXECUTE
  only), and `proconfig` stays empty. Both were confirmed on local and prod.
- **Default privileges are wider than the idiom's GRANT.** Supabase's default
  privileges gave `anon` and `authenticated` INSERT, UPDATE, DELETE, TRUNCATE,
  TRIGGER and REFERENCES on the new table. The FIX-1217 idiom only *adds*
  SELECT. That is the platform posture: `officials` and the two FIX-1217
  tables read identically on prod. RLS is the control, and on local an anon
  write was refused (401 / 0 rows). PostgREST exposes no TRUNCATE. I filed
  nothing, because `20260531000000_rls_hardening_safe.sql` is where the
  per-table REVOKE pattern already lives, if the platform ever wants it here.
- **Historical promotions can't be backfilled.** Since FIX-248 (278 promoted
  in one night once), the RPC has recorded only the loser's CAND_ID (in
  `prior_fec_candidate_ids`), never the deleted UUID. The eleven are
  recoverable only because cc-194's plan wrote them down.
- **Two prompt figures were stale.** The quoted live-body md5 `30a6b4a4` was
  the FIX-1195 body's; the live one is `648fe215`. The open-count forecast
  left out the conditional filing.
- **A design edge worth knowing.** `CHECK (old_id <> new_id)` plus the
  chain-collapse UPDATE would abort a promotion if a redirect `candidate →
  elected` ever existed. The invariant rules that out: the candidate is a
  live row, and only deleted ids are recorded. But a hand-inserted row that
  violated the invariant would turn into a failed promotion, not a silent
  self-loop.
- **A tooling trap I hit again.** Git Bash rewrote `fix:add --title
  "/institutions/…"` to `C:/Program Files/Git/institutions/…`. I repaired the
  bullet before committing (memory `reference_git_bash_leading_slash_args`).
