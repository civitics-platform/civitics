## 3. The `Reopens:` dedup key, as implemented

A closing row still keys on `(id, sha)`. A reopen row **cannot**: its sha column
is the literal `reopen`, so `(id, 'reopen')` would collapse every reopen of one
id into the first and silently drop a second, genuine one.

```js
doneLogKey(entry) =
  entry.sha !== "reopen"
    ? `${entry.id}|${entry.sha}`
    : `${entry.id}|reopen|${/^reopened by ([0-9a-f]{7,40})\b/.exec(entry.note)?.[1] ?? entry.note}`
```

The commit sha rides in the note (`reopened by <sha> <subject>`), which is where
the key reads it from — on **both** sides, so an existing row and a re-scanned
trailer produce the same key. Three properties, each a test case:

- two reopens of one id on **different** commits both land;
- one commit re-scanned dedups to the same key;
- the 22 **hand-written** reopen rows already in the log carry no sha in their
  note, so they key on the note text and can never collide with a trailer
  reopen.

`done.log`'s **format is unchanged** — this is purely a read-side key. The
trailer also carries `commitSha` on the in-memory object so the FIX-461
off-trunk filter can judge it; without that, a `Reopens:` on an unmerged branch
would classify as "unknown" (not hex) and sail straight through the guard.

## 7. Refused, stopped, or contradicting the design

Nothing was refused and no item was dropped. Six things the tree contradicted:

**1. `.claude/cc.config.json` cannot be versioned in this repo.** The prompt
specified it. `.gitignore` line 3 excludes `.claude/*` and negates only
`agents/`, `commands/`, `hooks/` and `settings.local.json` — so a config there
would exist on one machine only, the opposite of a shared convention. CLAUDE.md
requires explicit confirmation for `.gitignore` changes, so I did not make one.
The versioned config is `docs/cc/cc.config.json`; `.claude/cc.config.json` is
read first as a machine-local override. **If you want the prompt's original
path, the fix is a one-line `!.claude/cc.config.json` negation — say so and I
will add it.**

**2. The Stop hook belongs in `settings.local.json`, not `settings.json`.** Same
gitignore rule; `settings.json` is untracked here, `settings.local.json` is the
tracked one. The prompt asked me to say if the layout argued for it. It does.

**3. "Six removed characters per line" is four.** `- [x] ` → `- ` removes
`[`, `x`, `]`, ` `. Minor, but the strip tool asserts the exact byte delta and
refuses to write on a mismatch, so the number had to be right.

**4. The prompt said `fixes-archive.mjs`, `fixes-housekeep.mjs` and
`fix-add.mjs` need "no behaviour change". All three needed a code change to
*preserve* their behaviour.** Every one of them keys on a bullet regex
containing `\[`, and after the strip those match nothing:

- `fix-add.mjs`'s `findInsertionIdx` would have silently relocated every new
  bullet from "after the last bullet in the section" to "directly under the
  header" — a silent reordering of the backlog, on every future `fix:add`.
- `fixes-housekeep.mjs` would have stopped seeing any bullet at all: zero ids
  assigned, zero format warnings, and no error. Its entire job would have
  become a no-op that reported success.
- `fixes-archive.mjs`'s cut index and count would have found nothing under
  `## COMPLETED`.

Hence `scripts/lib/fixes-md.mjs`: the bullet shape in one place, because the
thing that had to change had to change in five files at once.

**5. The replacement bullet rule needed two clauses I did not expect, and I
found them by measuring rather than reasoning.** With the checkbox gone, "a
top-level `- ` line" is not sufficient:

- `docs/FIXES.md`'s **preamble** holds five priority-key lines that *do* start
  with a priority emoji (`- 🔴 Critical — …`). Without a section gate,
  `fixes:housekeep` would have assigned FIX ids to the priority key on its next
  run, and `fix:add` would have counted them as bullets.
- `docs/archive/fixes-archive.md` holds 5 **indented** `- ` continuation lines
  inside archived bullet bodies. Anchoring at column 0 separates them exactly —
  all 407 live and all 1,105 archived bullets are top-level, 0 indented.

A related coverage loss I had to repair rather than accept: `warnFormat`'s
"missing priority emoji" warning became unreachable for a hand-typed bullet
with neither emoji nor marker, because such a line is no longer recognised as a
bullet at all. Before the strip the checkbox made it visible. `fixes:housekeep`
now reports it explicitly as *"not recognised as a FIX bullet"* — that class is
the whole reason the script exists.

**6. The `cc:verify` test found three real bugs in `cc:verify` while it was
being written**, all in the front-matter parser, all of the shape "wrong but
green":
- a comma inside a commit subject split the map pair, silently truncating every
  subject to its first clause (`"feat(x): a, b"` → `"feat(x): a"`);
- `prod_writes:` written with no value parsed as an empty array, which is
  **truthy**, so `if (!fm.prod_writes)` treated *omitted* as *present* and
  passed;
- same for `head_after:`.

All three are fixed and each has a case. This is the argument for the verifier
in one paragraph: two of the three were checks that would have reported PASS on
a report that said nothing.
