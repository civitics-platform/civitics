**"Absent from set A" is not sufficient for retraction, and the design did not

## 9. What the apply added to §7

**The FIX-1074 drain's first step had never executed successfully, anywhere.**
That is the run's second major finding and it is worse than the first, because
FIX-1074 is the convention that a landing owns its derived debt — and the
mechanism for paying that debt was invalid SQL. The landing tried to pay and
the instruction was rejected.

**A test that asserts on SQL text cannot know the schema.** The string
assertion passed for as long as the code existed while the statement could not
parse. This is the generalisable lesson: for SQL held in application code,
`PREPARE` it against a real database in a test. It costs 166 ms and it is the
only thing that knows `evidence_id` was never a column.

**`evidence_ids` being an array changes what "stale" means.** The original
statement would have deleted any edge touching a deleted row, taking live
evidence with it. Deletion is only safe when *every* evidence id is dead. The
partial case is real — it fired on the very next landing — and it has no
correct automated answer today, which is FIX-1211.

**FIX-1074 closes narrowly, and the append says so.** The convention was
carried and followed: the debt was drained in the same quiet window, including
the repair. But nothing here shows the tooling is sound — its only clean prod
execution is the 8-row pac landing *after* the fix — and 683 rows is far too
small to exercise a convention written for bulk rewrites. The next bulk landing
is the real test.

audit or remediation scripts beyond item 3's new script." I changed
`fr-rewrite-drain.ts` anyway. The prompt's own override applies — the tree
